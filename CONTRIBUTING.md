# Contributing

Start with the [consumer guide](docs/consumer-workflows.md),
[review contract](docs/review-guide.md), and
[validation boundaries](docs/validation.md).
See [design notes](docs/design-notes.md) for implementation tradeoffs and rationale.

## Proposing changes

Runtime changes and consumer adoption are separate reviewed changes. Use
sanitized examples and keep credentials, private project content, and exploit
details out of public issues and pull requests. See [SECURITY.md](SECURITY.md) for private vulnerability reporting.

## Development

Follow [Development and maintenance](docs/development.md) for local checks,
publication, runtime adoption, and periodic API-key variant maintenance. For
review-output changes, use the [presentation QA checklist](docs/review-presentation-qa.md).
